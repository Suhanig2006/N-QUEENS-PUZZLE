What do these counts mean?

Checked: candidate squares the solver tested. Unsafe: candidates rejected because a queen attacks them. Backtracks: queens removed after searching below that position. Solutions found: complete, safe boards reached. Time: animation time, not CPU runtime.

The problem

Place N queens safely

Place one queen in every row of an N × N board so that no pair shares a column or diagonal. Rows are handled one at a time, so row conflicts cannot occur.

  1. Start at row 0.
  2. Try each column in that row.
  3. Reject a column if an earlier queen attacks it.
  4. For a safe square, place a queen and recurse to the next row.
  5. When a row has no safe column, return and try another choice.
  6. When row N is reached, record one complete solution.
Pseudocode

Backtracking search

search(row):
  if row == N:
    record a solution
    return

  for each column:
    if column is safe:
      place queen
      search(row + 1)
      remove queen  // backtrack

The solver explores every safe branch, so it can count all solutions rather than stopping at the first one.

Connected to the C code

Where the algorithm lives

conflict_reason(row, col) checks earlier rows for matching columns and diagonals; the result classifies unsafe candidates.
trace_search(row) tries columns, records trace events, places a safe queen, and recurses.
record_event(...) captures each try, reject, placement, solution, dead end, and backtrack for the animation.
placement[row] = -1 clears a queen after the recursive branch returns.
emit_trace(...) embeds these events in the generated HTML. The browser replays those exact C events.
